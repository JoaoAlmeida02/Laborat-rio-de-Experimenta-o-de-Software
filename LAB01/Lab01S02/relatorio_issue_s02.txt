# Sprint 2 - Lab01S02 - RQ05 e RQ06

## 1. Objetivo
Esta atividade corresponde à análise e validação dos dados referentes às Questões de Pesquisa 05 (RQ05) e 06 (RQ06), com base no conjunto de dados de 1.000 repositórios mais estrelados do GitHub coletados anteriormente pelo grupo. A análise visa investigar a relação entre a popularidade dos repositórios e suas linguagens primárias (RQ05), bem como a taxa de resolução de issues (RQ06).

## 2. RQ05 - Linguagens de programação

*   **Como a linguagem primária foi obtida:** Através do campo `primaryLanguage { name }` no nó de cada repositório retornado pela API GraphQL.
*   **Tratamento de valores ausentes/N/A:** Repositórios sem linguagem primária identificada (por exemplo, repositórios contendo apenas documentação, listas ou dados) que retornaram valor nulo da API foram devidamente catalogados e tratados com o rótulo "N/A" (Not Available).

## 3. RQ06 - Issues fechadas

*   **Pergunta da RQ06:** "Sistemas populares possuem um alto percentual de issues fechadas?"
*   **Métrica utilizada:** Proporção de issues fechadas em relação ao total de issues criadas.
*   **Fórmula utilizada:**
    $$\text{percentual de issues fechadas} = \frac{\text{issues fechadas}}{\text{total de issues}} \times 100$$
    onde:
    $$\text{total de issues} = \text{issues abertas} + \text{issues fechadas}$$
*   **Metodologia de coleta:** O script do grupo consultou a API GraphQL do GitHub obtendo a contagem total de issues com estado `OPEN` (mapeado para `issuesOpen`) e estado `CLOSED` (mapeado para `issuesClosed`).
*   **Tratamento de repositórios sem issues:** Repositórios com zero issues totais (`total_issues == 0`) receberam o rótulo "N/A" (Not Available) para o campo de razão/percentual a fim de evitar erros de divisão por zero.
*   **Quantidade de repositórios analisados:** 1.000 repositórios.
*   **Mediana do percentual de issues fechadas:** 87.60% (calculada sobre os 957 repositórios válidos que possuem alguma issue).
*   **Média:** 80.23%
*   **Mínimo:** 7.70%
*   **Máximo:** 100.00%
*   **Quantidade de repositórios sem issues:** 43 repositórios (4.30%).
*   **Quantidade de repositórios com percentual alto de issues fechadas:**
    Adotando a linha de corte metodológica de >= 80% de issues fechadas como indicativo de alta resolução de demandas:
    *   **618 repositórios** (61.80% do total de 1.000 repositórios, ou 64.58% dos 957 que possuem issues) apresentam taxa >= 80%.
    *   **433 repositórios** (43.30% do total de 1.000 repositórios, ou 45.25% dos 957 que possuem issues) apresentam taxa >= 90%.
*   **Hipótese informal da RQ06:** A hipótese informal inicial é que sistemas muito populares possuem um alto percentual de issues fechadas, uma vez que a alta popularidade e grande número de estrelas atraem uma comunidade de mantenedores e colaboradores ativos dedicados a responder rapidamente e resolver/fechar as issues abertas, mantendo a saúde do projeto.
*   **Discussão preliminar da hipótese:** A hipótese foi confirmada pelos dados reais. A média (80.23%) e a mediana (87.60%) de issues fechadas são bastante elevadas, e mais de 64% dos repositórios com issues apresentam taxas de resolução iguais ou superiores a 80%. Isso demonstra que a maioria esmagadora das issues criadas em repositórios muito populares é de fato fechada, o que corrobora a premissa de que tais projetos contam com gestão activa de issues e ciclo de vida dinâmico.

## 5. Problemas e limitações

*   **Dinâmica Temporal das Issues:** O número de issues abertas e fechadas varia continuamente no GitHub. Como a coleta foi efetuada em um ponto específico do tempo, os números contidos no arquivo CSV são estáticos e representam um instantâneo temporal. Qualquer comparação futura contra a interface viva do GitHub resultará em pequenas discrepâncias.
*   **Repositórios de Documentação/Listas (N/A):** Um total de 87 repositórios do conjunto (8.70%) não possuem linguagem primária atribuída (salvos como "N/A"), pois contêm apenas arquivos de documentação, coleções de links (como repositórios "awesome-*") ou arquivos de configuração. Embora sejam populares em termos de estrelas, eles não são "sistemas de software" no sentido estrito, o que afeta a análise da RQ05.
*   **Proporção de Issues e "N/A" para RQ06:** 43 repositórios (4.30%) não possuem nenhuma issue (aberta ou fechada) registrada na API, necessitando de tratamento especial para evitar divisão por zero (atribuição de "N/A"), reduzindo a amostra analisada da RQ06 para 957 repositórios.
*   **Inconsistências Conceituais:** A contagem total de issues na API GraphQL do GitHub reflete todas as issues registradas ao longo da vida do repositório, mas não diferencia issues spam de issues válidas, nem o histórico completo de reaberturas.

## 6. Conclusão

Na Sprint 2 (Lab01S02), realizou-se a consolidação das análises das Questões de Pesquisa RQ05 e RQ06 a partir dos dados previamente coletados dos 1.000 repositórios mais estrelados do GitHub. Os resultados demonstraram que o topo de linguagens primárias de repositórios estrelados (liderado por Python, TypeScript e JavaScript) se alinha com as linguagens mais populares da plataforma segundo o GitHub Octoverse 2024, apresentando desvios pontuais decorrentes do perfil de repositórios que acumulam mais estrelas. Para as issues, constatou-se que repositórios populares exibem taxas de resolução elevadas, com média de 80.23% e mediana de 87.60% de issues fechadas, confirmando a existência de gerenciamento ativo em projetos de grande visibilidade.
